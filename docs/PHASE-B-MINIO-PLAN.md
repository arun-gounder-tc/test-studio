> **Companion to `POSTGRES-MIGRATION-PLAN.md` §Phase B.**
> Phase A (Postgres + Multi-project) complete hai. Ab run artifacts (video, screenshots, reports) ko local FS se MinIO me move karna hai, aur UI presigned URLs se fetch kare.
>
> **Created:** 2026-05-10
> **Status:** Awaiting approval before code changes start

---

## 1. Goal

Aaj run artifacts `.test-studio/runs/{videos,screenshots}/...` me local disk pe likhe jaate hain, aur server `fs.createReadStream` se serve karta hai. Phase B ke baad:

- **Object storage source-of-truth:** har run ke video/screenshots/report MinIO bucket me upload honge
- **DB-tracked:** `run_artifacts` table me ek row per file (already schema me hai, currently unused)
- **Presigned URL playback:** UI `<video>` aur `<img>` tags directly MinIO se fetch karenge (server proxy nahi)
- **Restart-safe:** server/container restart ke baad bhi past runs ka video play hota rahe — abhi nahi hota kyunki `runnerService.runs` Map me hi videoPath rakhta hai
- **Pluggable:** dev me MinIO local Docker me, prod me S3/R2/GCS swap-in trivial via `Storage` interface
- **Lifecycle:** upload safal ke baad local copy delete (configurable via env)

## 2. Scope

### In scope
- `Storage` interface + 2 implementations: `MinioStorage` (default), `LocalFsStorage` (dev fallback / no-MinIO mode)
- After-run upload hook in `cypress-runner.service.ts`
- `run_artifacts` row per uploaded file (kind = video | screenshot | report)
- New `GET /api/test-studio/runs/:id/artifacts` endpoint (typed list with presigned URLs)
- Existing `GET /runs/:id/video` aur `/runs/:id/screenshots*` ko **302 redirect** kar dena MinIO presigned URL pe (backward-compat; UI bina change ke kaam karta rahega)
- Env vars + `.env.example` update pointing at deployed MinIO endpoint
- `import-tests` style script: `npm run upload-existing-artifacts` — past `.test-studio/runs/` walk karke MinIO me push karta hai (idempotent, optional)

### Out of scope (later phases)
- Chat image attachments → Phase C (uses same `Storage` interface, but separate flow)
- Full `docker-compose.yml` with Postgres + UI + server → Phase E
- S3/R2/GCS providers — interface ready, implementations on demand
- Bucket lifecycle policies (auto-delete after N days) — production hardening Phase E
- Virus/MIME scanning — Phase G

## 3. Locked decisions

| # | Decision | Choice | Reason |
|---|---|---|---|
| 1 | Object storage SDK | **`minio` npm package** (S3-compatible) | Officially maintained; works with MinIO, AWS S3, R2, GCS via endpoint config |
| 2 | Bucket strategy | **Single bucket `test-studio`** with prefixes (`run-artifacts/<runId>/...`, `chat-uploads/<convId>/...`) | Easier IAM; matches migration plan §6 |
| 3 | URL access | **Time-bound presigned URLs** generated by server (TTL: 60 min for video, 15 min for screenshots) | UI never sees credentials; presign ROI worth the slight complexity |
| 4 | Existing routes | **Keep `/runs/:id/video` aur `/screenshots/*` as 302 redirects** to presigned URLs | UI doesn't need to change; clean cutover |
| 5 | Upload timing | **Post-run, in `child.on('close')`** — after final flush, before status update completes | Run is "done" only when artifacts persist; failures here mark `errored` |
| 6 | Local file cleanup | **Delete after successful upload** (configurable via `KEEP_LOCAL_ARTIFACTS=true`) | Disk pressure relief; dev override possible |
| 7 | Dev-mode fallback | **`STORAGE_DRIVER=local`** uses `LocalFsStorage` (writes to `.test-studio/storage/...` instead of MinIO) | No MinIO dependency for quick dev |
| 8 | Failure handling | **Best-effort upload, non-fatal** — if MinIO down, run still completes; warning logged, `run_artifacts` rows not created | Don't fail user's run because of infra glitch |
| 9 | Content type detection | **Hardcoded by file extension** (`.mp4` → `video/mp4`, `.png` → `image/png`) — no `mime-types` lib | Only 3 file kinds; over-engineered to add a dep |
| 10 | Retry/backoff on upload | **Single attempt + log on failure** for MVP | Phase F (queue) will add proper retry semantics |

## 4. Storage interface

New folder: `studio-server/src/services/storage/`

```typescript
// storage.interface.ts
export interface PutObjectInput {
  key: string;                  // 'run-artifacts/<runId>/video.mp4'
  body: Buffer | NodeJS.ReadableStream;
  contentType: string;
  sizeBytes?: number;           // optional; useful for streams
}

export interface PutObjectResult {
  key: string;
  sizeBytes: number;
  etag?: string;
}

export interface PresignedUrlOptions {
  expiresInSec?: number;        // default 900 (15 min)
}

export interface Storage {
  /** Idempotent — same key + same body is a no-op overwrite */
  putObject(input: PutObjectInput): Promise<PutObjectResult>;
  /** Time-bound HTTPS URL */
  getPresignedUrl(key: string, options?: PresignedUrlOptions): Promise<string>;
  /** Existence check (used by integrity sweeps) */
  objectExists(key: string): Promise<boolean>;
  /** Soft delete — used by archive/cleanup flows */
  deleteObject(key: string): Promise<void>;
  /** Streamable read — only used by server-side proxy fallback (rare) */
  getObjectStream(key: string): Promise<NodeJS.ReadableStream>;
}
```

### Implementations

**`minio.storage.ts`**
- Constructed from env: `MINIO_ENDPOINT` (default `http://localhost:9000`), `MINIO_ACCESS_KEY`, `MINIO_SECRET_KEY`, `MINIO_BUCKET` (default `test-studio`)
- `putObject` → `client.putObject(bucket, key, body, sizeBytes, { 'Content-Type': contentType })`
- `getPresignedUrl` → `client.presignedGetObject(bucket, key, expiresInSec)`
- Bucket auto-create on boot if missing

**`local-fs.storage.ts`**
- Writes to `${PROJECT_ROOT}/.test-studio/storage/<key>` (creates parent dirs)
- `getPresignedUrl` returns `${SERVER_BASE_URL}/api/test-studio/storage/<key>?token=<short-jwt>` — internal proxy route serves the file (no real signing; dev only)
- Used when `STORAGE_DRIVER=local` (no Docker required)

**Singleton selection (`storage/index.ts`)**
```typescript
export const storage: Storage = process.env.STORAGE_DRIVER === 'local'
  ? new LocalFsStorage()
  : new MinioStorage();
```

## 5. Server changes

### 5.1 Runner service — post-run upload hook

`cypress-runner.service.ts` ke `child.on('close')` ke andar, **status update karne se pehle**:

```typescript
// Pseudocode after existing scenario/status logic, before RunsRepo.updateStatus
if (record.videoPath || record.screenshotsDir) {
  await this.uploadArtifacts(record);
}
```

New private method `uploadArtifacts(record: RunRecord)`:
1. **Video** → if `record.videoPath` exists:
   - key = `run-artifacts/${record.id}/video.mp4`
   - `storage.putObject({ key, body: createReadStream, contentType: 'video/mp4', sizeBytes: stat.size })`
   - `RunsRepo.attachArtifact({ runId, kind: 'video', minioKey: key, contentType: 'video/mp4', sizeBytes })`
   - if `process.env.KEEP_LOCAL_ARTIFACTS !== 'true'` → `fs.unlinkSync(record.videoPath)`
2. **Screenshots** → walk `record.screenshotsDir`:
   - For each `.png` / `.jpg`:
     - key = `run-artifacts/${record.id}/screenshots/${filename}`
     - upload + attachArtifact (kind: 'screenshot', scenarioName: parsed from filename `Login -- failure (1).png` → `Login`)
     - delete local file after success
   - rmdir empty parent
3. **Report** → upload `.test-studio/last-run.json` as `run-artifacts/${runId}/cucumber-report.json` (kind: 'report')
4. Wrap whole thing in try/catch — on error: log + continue (run status stays correct)

### 5.2 New routes

**`GET /api/test-studio/runs/:id/artifacts`**
```typescript
// Returns:
{
  artifacts: [
    {
      id: 'uuid',
      kind: 'video' | 'screenshot' | 'report',
      contentType: 'video/mp4',
      sizeBytes: 12345678,
      scenarioName: 'Login flow' | null,
      url: 'http://minio:9000/test-studio/...?X-Amz-Signature=...',  // presigned, 60min for video, 15min others
      createdAt: '2026-05-10T...'
    },
    ...
  ]
}
```

Implementation in `runs.routes.ts`:
- Read `run_artifacts` rows via `RunsRepo.listArtifacts(runId)`
- For each row, generate fresh presigned URL (different TTL by kind)
- Return assembled array

### 5.3 Modified routes — backward-compat redirects

**`GET /runs/:id/video`**
- Try DB first: `RunsRepo.listArtifacts(runId)` → find `kind='video'`
- If found → `res.redirect(302, await storage.getPresignedUrl(key, { expiresInSec: 3600 }))`
- Else → fallback to existing in-memory `record.videoPath` (for active runs whose upload hasn't completed)
- Else → `404`

**`GET /runs/:id/screenshots`**
- Read `run_artifacts` rows where `kind='screenshot'`
- Build `files: [{ name, url, scenarioName }]` with presigned URLs
- Fallback to in-memory `record.screenshotsDir` if none

**`GET /runs/:id/screenshots/:filename`**
- Find matching `run_artifact` row by key suffix
- 302 redirect to presigned URL
- Old direct file serving stays as fallback

> **Note:** UI consumes `runsService.videoUrl(id)` and the screenshots `url` field as-is. 302 redirect means **zero UI changes required** for video/screenshots. New `/artifacts` endpoint is a future-friendly typed surface for replay/detail pages (Phase D will use it).

### 5.4 Bucket initialization

On server boot, after Sequelize sync:
```typescript
await storage.ensureBucket();   // method added to Storage interface
```
- `MinioStorage.ensureBucket()` → `client.bucketExists(bucket)`; if false → `client.makeBucket(bucket)`
- `LocalFsStorage.ensureBucket()` → `fs.mkdirSync('.test-studio/storage', { recursive: true })`

## 6. MinIO setup

This project uses an **externally hosted MinIO instance** — no local Docker needed. Point the server at it via env vars in `studio-server/.env`:

```bash
STORAGE_DRIVER=minio
MINIO_ENDPOINT=https://your-minio.example.com
MINIO_ACCESS_KEY=...
MINIO_SECRET_KEY=...
MINIO_BUCKET=test-studio
```

The bucket is auto-created on first boot via `storage.ensureBucket()` if the credentials have `s3:CreateBucket` permission; otherwise pre-create it manually in the MinIO console.

### Dev fallback (no MinIO)

If you don't want any object storage running:
```bash
STORAGE_DRIVER=local
SERVER_BASE_URL=http://localhost:3001
```
Files land in `.test-studio/storage/...` and are served via `/api/test-studio/storage/*` proxy. **Dev only — no signature validation.**

## 9. Migration of existing runs

Optional one-shot script: `studio-server/scripts/upload-existing-artifacts.ts` (`npm run upload-existing-artifacts`).

```
Steps:
1. Walk .test-studio/runs/videos/*.mp4 and .test-studio/runs/screenshots/*/
2. For each video filename, try to match to a runs.id (filename matches spec, runs.testId points to test slug)
   — if no match found, skip with a warning (orphan local artifacts)
3. If matched and run_artifacts row absent for that runId+kind combo → upload + insert row
4. Print summary: "Uploaded N videos, M screenshots; K orphans skipped"
5. Idempotent — skips files that already have run_artifacts rows
6. Local files left in place by default (delete with --cleanup flag)
```

This is **optional** for Phase B done-criteria — fresh runs after the cutover are what matter most.

## 11. Risks & mitigations

| Risk | Mitigation |
|---|---|
| Upload time delays SSE `finish` event by 5–30s on big videos | Move upload to `setImmediate` after status update; SSE emits `finish` first, then `artifacts-uploaded` event |
| Presigned URL expires mid-video-playback | TTL 60 min for video; UI re-requests on `error` event from `<video>` |
| Orphaned MinIO objects when run row deleted | Phase B: hard cascade on `runs.id` already drops `run_artifacts` rows; periodic `mc rm --recursive` sweep added in Phase E |
| MinIO endpoint typo silently fails | Boot-time `ensureBucket()` errors loudly; readiness check fails fast |
| Local-fs presign forgery (since no real signing) | LocalFsStorage is dev-only; documented as such; production must use MinIO |
| Big screenshots dir takes long to upload (e.g. 50 failures) | Parallel upload with `Promise.all` capped at 5 concurrent |
| Browser CORS error fetching from MinIO `:9000` | MinIO defaults already allow `*`; if hardened later, set explicit `cors-config.json` via `mc admin config set` |

## 13. API contract summary

### New
| Method | Path | Returns |
|---|---|---|
| `GET` | `/api/test-studio/runs/:id/artifacts` | `{ artifacts: { id, kind, contentType, sizeBytes, scenarioName, url, createdAt }[] }` |
| `GET` | `/api/test-studio/storage/*` | (LocalFsStorage proxy only — dev mode) Streams file with token check |

### Modified (behavior only; URL unchanged)
| Method | Path | Old behavior | New behavior |
|---|---|---|---|
| `GET` | `/runs/:id/video` | Streams local mp4 | 302 → MinIO presigned (TTL 60 min); falls back to local stream if not yet uploaded |
| `GET` | `/runs/:id/screenshots` | Lists from local dir | Lists from `run_artifacts`; falls back to local dir |
| `GET` | `/runs/:id/screenshots/:filename` | sendFile from local dir | 302 → MinIO presigned (TTL 15 min); falls back to local file |

### Unchanged
- `POST /runs`, `GET /runs`, `GET /runs/:id`, `GET /runs/:id/stream`, `GET /runs/:id/logs` — all stay as Phase A
